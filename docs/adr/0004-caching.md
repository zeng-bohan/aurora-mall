# 0004 — 缓存体系：经典三防 + 双写一致性对照

日期：2026-09-28 · 状态：Accepted

## Context

商品详情等热点读数据需要缓存；缓存穿透 / 击穿 / 雪崩与 DB-缓存一致性是分布式系统的核心经典问题，需要在项目中"做实"而非只停留在概念。

## Decision

- **商品/详情缓存**：Cache Aside + 空值缓存 + 布隆过滤器（防穿透）+ 逻辑过期 + 互斥重建（防击穿）+ 随机 TTL（防雪崩）
- **库存**：Redis 预扣（Lua 原子）+ 消息/定时异步落库 + 定时对账（见 ADR-0003）
- **一致性**：主方案"先更 DB 再删缓存 + 延迟双删"；另做 **Canal 订阅 binlog 删缓存**的对照实验模块（小而精）
- **分布式锁**：Redisson（可重入 + 看门狗续期）

## Consequences

- 布隆过滤器、逻辑过期等组件自己实现（不引现成库），作为可讲的基础设施代码
- Canal 对照实验控制在 2-3 天量级，做小做精
- **锁的分层**：缓存重建互斥用轻量 SETNX 守卫（10s TTL、单飞重建，不需要看门狗）；决策中的 Redisson 保留给 M2 起的通用分布式锁（库存预扣、秒杀），届时再引入依赖。互斥重建是"单飞"机制而非完整分布式锁，两者不混用。

## 后续加固（2026-09-30 评审）

- 布隆过滤器位图改 `AtomicLongArray`（写 CAS、读 get），启动播种/请求读/管理写并发正确。
- 多实例局限：每 JVM 一份本地位图，实例 A 新建商品后实例 B 的过滤器不含该 id，读路径直接 404（"无假阴性"承诺只在单实例成立）。当前以**定期重播种**（默认 5 分钟，整体构建新过滤器原子换入）收敛窗口；真正的共享版（Redis 位图 + 分批重建）按计划留给 M5 秒杀场景一并落地。
