# 0003 — 分布式事务：消息最终一致性为主，Seata AT 对照

日期：2026-09-28 · 状态：Accepted

## Context

订单 ↔ 库存 ↔ 支付跨服务一致性是本项目最核心的设计点。备选：RocketMQ 事务消息最终一致性、Seata AT 同步强一致、TCC 手写补偿。

## Decision

**混合方案**：

- **主链路用消息最终一致性**：下单 = Redis 预扣库存（Lua 原子，防超卖）→ 创建订单（待支付）→ 30 分钟延迟消息关单并回滚库存 → 支付回调后库存异步落库；跨服务事件走 RocketMQ 事务消息 + 本地消息表
- **Seata AT 做对照实验**：选一个适合强一致的局部场景（订单创建 + 积分赠送）落地，与主链路方案形成可讲述的对比
- 定时对账任务作为最终兜底，覆盖消息丢失与窗口期不一致

## Consequences

- 主链路存在一致性"窗口期"（下单成功到库存落库之间），需在文档中讲清补偿与对账如何兜底
- 放弃 TCC：业务侵入大、开发成本高，AT 对照已足够形成方案对比
